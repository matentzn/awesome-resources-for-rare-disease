# Contribution Guidelines

Thank you for your interest in contributing to Awesome Resources for Rare Disease!

## Adding a Resource

Please ensure your pull request adheres to the following guidelines:

- **Search previous suggestions** before making a new one to avoid duplicates.
- **List each resource once**, in the section that matches what it mainly is. Software (including phenotype-driven rankers such as Exomiser) goes under Analysis Tools & Software, even when it is used for diagnosis. If a resource also offers data or an API, link them from the same entry instead of adding a second one.
- **Make an individual pull request** for each suggestion.
- **Use the following format:** `- [Resource Name](URL) - Brief description.`
- **Descriptions should be concise** and explain what the resource is, not just the name.
- Descriptions should end with a period.
- **Check your spelling and grammar.**
- **New categories or improvements to the existing categorization are welcome.**
- **The pull request and commit should have a useful title.**

## Scope

The list is for researchers, bioinformaticians, data engineers and developers who work with rare disease data. A resource belongs here if it passes this test: **can someone working with rare disease data query it, download it, run it, adopt it as a standard, or apply to it for data or samples?**

In scope:

- knowledge bases, ontologies, terminologies and data standards
- variant databases, datasets and benchmarks
- registries, biobanks and pooled data platforms that researchers can apply to
- diagnostic and patient-matching services, analysis tools and software
- research programmes and communities that run research infrastructure or agree on data standards
- catalogues and directories of such resources

Out of scope, however valuable:

- patient and family support, advocacy and funding organisations (list the registry, dataset or tool they run instead)
- events, conferences, podcasts, social media groups and other media
- individual patient-organisation registries hosted on a shared platform such as CoRDS or IAMRARE (the platform is listed)

Families looking for support are better served by [Librarey](https://www.librarey.com/) and the [Resource Ecosystem](https://boycelab.github.io/rare-resources/).

## Quality Standards

The most important criterion comes first: **the diseases a resource addresses must be predominantly rare.** A resource that is useful for rare disease work but serves common and rare disease alike (general genomics, ontology or clinical tooling) belongs in [EXCLUDED.md](EXCLUDED.md), however good it is.

Beyond that, resources should be:

- **Recently maintained** - updated within roughly the last two years (a new release, a data refresh, commits, or visible operational activity). This is a judgement call rather than a hard cutoff: a stable classification or standard that is still the current edition counts as maintained, while a tool whose last release is years old does not. Resources that are no longer updated should be noted or removed.
- **In scope** as described [above](#scope). Single-disease resources (e.g. a variant database or registry for one disease) are in scope.
- **Freely accessible** or at least have a free tier for basic access. A resource that is an open point of coordination also qualifies even if its data is closed: anyone can find it and apply to contribute to or use it, as with most patient registries, biobanks and controlled-access datasets. Access may involve an application, a data access committee, or fees for data release.
- **Reputable** - from established organizations, research institutions, or well-maintained projects.

## Updating Your Pull Request

If asked to update your pull request, please edit your PR directly rather than opening a new one.

Thank you for your contributions!
